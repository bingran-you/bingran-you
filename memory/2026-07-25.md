**Gotcha for future J.A.R.V.I.S. instances:** `git status` showed 6 submodules as `modified` when the worktree was cold. That was NOT "the index is stale, please bump." The submodule **checkouts** (working-tree copies) were behind the SHAs that main tracks — probably because a previous session had bumped the index but left this worktree's `.git/worktrees/.../modules/` copies on the older SHAs. Fix: `git submodule update --init <path>` for each — bring the checkout forward to the index. Do NOT `git add` those "modifications" and open a PR: the diff would be a downgrade of every submodule pointer.

Rule of thumb: before opening a "bump submodules" PR, verify direction with

```
for sm in <list>; do
  idx=$(git ls-tree HEAD $sm | awk '{print $3}')
  head=$(cd $sm && git rev-parse origin/HEAD 2>/dev/null || git rev-parse origin/main 2>/dev/null)
  echo "$sm: upstream ahead of index by $(git -C $sm rev-list --count $idx..$head) commits"
done
```

If the number is 0 for every submodule, main is already fresh — sync the working tree with `git submodule update` and skip the PR.
