Quadratic-Time Algorithm for the
Maximum-Weight (k, l)-Sparse Subgraph Problem
Bence De ́ak1 Pe ́ter Madarasi2
Abstract
The family of (k, l)-sparse graphs, introduced by Lorea, plays a central role in combinatorial optimization and has a wide range of applications, particularly in rigidity theory. A key algorithmic challenge is to compute a maximum-weight (k, l)-sparse subgraph of a given edge-weighted graph. Although prior approaches have long provided an O(nm)-time solution, a previously proposed O(n2 + m) method was based on an incorrect analysis, leaving open whether this bound is achievable. We answer this que-
stion affirmatively by presenting the first O(n2 + m)-time algorithm for computing a maximum-weight (k, l)-sparse subgraph, which combines an efficient data structure with a refined analysis. This quadratic-time algorithm enables faster solutions to key problems in rigidity theory, including computing minimum-weight redundantly rigid and globally rigid subgraphs. Further applications include enumerating noncrossing minimally rigid frameworks and recognizing kinematic joints. Our implementation of -
the proposed algorithm is publicly available online.
Keywords: (k, l)-sparse graphs, pebble game algorithm, rigidity theory, efficient data structures
1 Introduction
Throughout this paper, let k and l be non-negative integers with l < 2k, let G = (V, E) be a loopless multigraph with n = |V | vertices and m = |E| edges, and assume that the edges e1, . . . , em are sorted in non-increasing order with respect to a given weight function. The graph G = (V, E) is called (k, l)-sparse if, for each subset X ⊆ V , the number i(X) of edges induced by X is at most max{k|X| − l, 0}. Furthermore, if G is (k, l)-sparse and has exactly max{k|V | − l, 0} edges, then we say th-
at G is (k, l)-tight. A graph is (k, l)-spanning if it contains a (k, l)-tight subgraph that spans the entire vertex set. A (k, l)-block of a (k, l)-sparse graph is a subset X ⊆ V that induces a (k, l)-tight subgraph. A (k, l)-component is an inclusion-wise maximal (k, l)-block. These definitions form the foundation of a rich theory, closely connected to matroids and rigidity, and they naturally lead to fundamental optimization problems that are the focus of this paper.
The concept of (k, l)-sparse graphs was first introduced by Lorea [1] as part of his work on matroidal families. Since then, these graphs have been the subject of extensive research, with numerous applications in various areas of mathematics and computer science. For example, (k, k)-tight graphs appeared in the work of Nash-Williams [2] and Tutte [3] as a characterization of graphs that can be decomposed into k edge-disjoint spanning trees. A classical result in rigidity theory, due to Laman [4], -
characterizes generic minimally rigid bar-joint frameworks in the plane as (2, 3)-tight graphs, while the rigid graphs correspond to the (2, 3)-spanning graphs. For a comprehensive overview of rigidity theory, see [5, 6]. A wide range of optimization and decision problems can be reduced to the maximum-size (k, l)-sparse subgraph problem, where k and l are fixed non-negative integers determined by the specific task. The goal is to find a (k, l)sparse subgraph of a given graph G = (V, E) that contai-
ns the maximum number of edges. A natural generalization is the maximum-weight (k, l)-sparse subgraph problem, where the goal is to find a (k, l)-sparse subgraph with maximum total weight under a given weight function on the edges. Many classical problems in graph theory can be viewed as special cases of this framework — for example, finding a maximum-weight spanning tree, a maximumweight subgraph that can be decomposed into k forests, or a maximum-weight rigid spanning subgraph in the plane.

In our paper, we provide a positive answer to this question: we present an algorithm that solves the maximumweight (k, l)-sparse subgraph problem in O(n2+m) time. Our approach combines a carefully designed data structure with a refined analysis, leading to both theoretical and practical advances. As a direct corollary, the maximumweight rigid subgraph problem — corresponding to the well-known case k = 2, l = 3 — can now be solved in quadratic time. Beyond its standalone significance, the maximum-w-

For example, our algorithm substantially improves the running time of approximation algorithms for the minimum-weight redundantly rigid and globally rigid subgraph problems [14] and their generalizations [13] in the metric case. Further applications include enumerating non-crossing minimally rigid frameworks [15], as well as recognizing kinematic joints [16]. An efficien-
t implementation of the algorithms discussed in this paper is publicly available online [17], and a detailed empirical evaluation can be found in [18].
The rest of the paper is organized as follows. Section 1.1 provides an overview of the classical augmenting-path algorithm — often referred to as the “naive” pebble game — for computing maximum-size and maximum-weight (k, l)-sparse subgraphs. In Section 2, we present our component-based variant of this algorithm, which forms the core of our contributions. This high-level approach relies on two auxiliary procedures for managing (k, l)components, whose implementation can be tailored to the specific -
setting of the problem. Our main contribution is presented in Section 3, where we give a complete implementation of these subroutines for the general range 0 ≤ l < 2k. Combining structural properties of (k, l)-components with an efficient data structure, we prove that the resulting algorithm achieves a running time of O(n2 + m), improving on the O(nm) bound of the naive approach. Finally, Section 4 addresses two notable special cases. First, we examine the case 0 ≤ l ≤ k, where the disjointness of-
 (k, l)-components allows for a simplified implementation reducing the space complexity from O(n2) to O(n). Second, we address the unweighted variant for the general range, in which a vertex-wise edge-processing strategy retains the O(n2 + m) running time while requiring only O(n) space. These results together establish a unified algorithmic framework for efficiently solving the maximum-size and maximum-weight (k, l)-sparse subgraph problem across the full range of parameters.
1.1 The naive augmenting-path algorithm
We overview the classical, or “naive”, version of the pebble game algorithm for finding a maximum-size or maximumweight (k, l)-sparse subgraph. We begin by stating two fundamental results that are essential for proving the correctness of the algorithm, and then present the algorithm itself.
Theorem 1 (Lorea, 1979 [1]). Let G = (V, E) be a graph, and define I = {F ⊆ E : (V, F ) is (k, l)-sparse}. Then M = (E, I) is a matroid.
We also need the following technical result, which can be derived from Hakimi’s Orientation Lemma [19]. Here we give a direct proof. Note that a similar lemma appeared as Lemma 1 in [8] for (k, l) = (2, 3).
Lemma 1. Let H = (V, F ) be a (k, l)-sparse graph, and let u, v ∈ V be two distinct vertices. Suppose D is an orientation of H in which each vertex has indegree at most k. Then:
1. If ρD(u) + ρD(v) < 2k − l, then H′ = (V, F ∪ {uv}) is also (k, l)-sparse.

We are now ready to describe the augmenting-path algorithm for finding a maximum-weight (k, l)-sparse subgraph. The algorithm is built on two key ideas:
• We iteratively construct the optimal subgraph H = (V, F ), considering the edges one by one in the order e1, . . . , em. Each edge e is inserted into H if and only if the resulting subgraph H′ = (V, F ∪ {e}) remains (k, l)-sparse.
• We maintain a k-indegree-bounded orientation D of the current subgraph F . For each edge e, we apply Lemma 1 together with the orientation-based procedure described above to determine whether the edge can be accepted. If H′ = (V, F ∪ {e}) is (k, l)-sparse, then we insert e into H and update D by inserting e with an orientation that preserves the k-indegree bound.
The correctness of this method immediately follows by Theorem 1 and Lemma 1. Algorithm 1 provides an implementation of this iterative approach.

2 The component-based algorithm
In Algorithm 1, checking for each edge whether it can be inserted into D without violating the sparsity condition takes O(nm) time in total. If we instead had access to an oracle that could determine in constant time whether an edge can be accepted, then augmenting paths would only need to be computed for the O(n) edges actually inserted, reducing the total running time to O(n2 + m). We construct such an oracle by leveraging the following structural properties of (k, l)-blocks and (k, l)-component-
s.
Lemma 2. Let X and Y be (k, l)-blocks of a (k, l)-sparse graph H = (V, F ) such that |X ∩ Y | ≥ 2. Then both X ∩ Y and X ∪ Y are (k, l)-blocks.
Proof. Let X, Y ⊆ V be distinct blocks of H such that |X ∩ Y | ≥ 2. Recall that iH (X) denotes the number of edges induced by X. By the supermodularity of this function, we have
k(|X| + |Y |) − 2l = iH (X) + iH (Y ) ≤ iH (X ∩ Y ) + iH (X ∪ Y ) ≤ k|X ∩ Y | + k|X ∪ Y | − 2l = k(|X| + |Y |) − 2l.
Since the left- and right-hand sides are equal, all inequalities must hold with equality, and hence X ∩ Y and X ∪ Y are blocks.
Corollary 1. Any two distinct (k, l)-components in a (k, l)-sparse graph H = (V, F ) intersect in at most one vertex.
Proof. Let X and Y be components with |X ∩ Y | ≥ 2. By the previous lemma, X ∪ Y is also a block. Since X ∪ Y contains both X and Y , it follows that X = Y , otherwise X or Y is not inclusion-wise maximal.
Corollary 2. Inserting a single edge into a (k, l)-sparse graph H = (V, F ) can form at most one new (k, l)component.
Proof. Let uv be the edge to be inserted, and let X and Y be two newly formed components. Since u, v ∈ X ∩ Y , we clearly have |X ∩ Y | ≥ 2. By Corollary 1, this implies that X = Y .
Corollary 3. The total size of the (k, l)-components in a (k, l)-sparse graph H = (V, F ) is O(n).
Proof. By Corollary 1, each edge in F is induced by at most one component. Since |F | ≤ max{kn − l, 0} = O(n), the number of components is O(n). A component inducing t edges has at most (t + l)/k < t/k + 2 vertices, so the sum of the sizes of all components is at most |F |/k + 2 · O(n) = O(n).
Let us now revisit our original problem and modify Algorithm 1 to achieve a faster running time. Our goal is to decide in constant time whether an edge uv can be inserted into the current subgraph H = (V, F ) without violating the sparsity condition. Clearly, H′ = (V, F ∪ {uv}) is (k, l)-sparse if and only if no (k, l)-component in H contains both u and v. To determine whether uv can be accepted, the algorithm must therefore check for the existence of such a (k, l)-component. If uv is inserted, th-
en a new (k, l)-component containing both u and v may form, and some existing (k, l)-components may cease being (k, l)-components, as they remain (k, l)-blocks but are no longer maximal. We introduce three subroutines to handle these operations efficiently:
• InCommonComponent(u, v) — checks whether there is a (k, l)-component containing both u and v.
• FindComponent(D, u, v) — returns the new (k, l)-component formed after inserting uv, or ∅ if no such (k, l)component appears.
• UpdateComponents(C) — updates the data structures representing the current set of (k, l)-components after a new (k, l)-component C is identified.
Temporarily treating these as black boxes, we obtain the following high-level algorithm.

Lemma 4. Let D be a k-indegree-bounded orientation of a (k, l)-sparse graph H = (V, F ) and let u, v ∈ V be distinct vertices such that ρD(u) + ρD(v) = 2k − l. If such a component exists, then it is exactly T .
Proof. Suppose that u, v ∈ T . Since S and T are disjoint, we have ρD(w) = k for each w ∈ T \ {u, v}. Furthermore, T has no incoming edges, so ρD(T ) = 0. By Lemma 3, T is a (k, l)-block, and hence u and v lie in a common component.

3 Implementation for the range 0 ≤ l < 2k
In this section, we describe the implementation of the InCommonComponent and UpdateComponents subroutines, thereby completing our O(n2 + m)-time algorithm that solves the maximum-weight (k, l)-sparse subgraph problem for the full range of parameters 0 ≤ l < 2k. We also provide a detailed analysis of the running time of the resulting algorithm.
To efficiently track the (k, l)-components in H = (V, F ), we use a bit matrix M ∈ {0, 1}V ×V , where Mu,v = 1 if and only if u and v lie in some common (k, l)-component. Alongside M , we also maintain a list C containing the set of the current (k, l)-components, each represented as a list of vertices. If l < k, we initialize M to zero and set C to the empty list; otherwise, we set M = I and initialize C with all singleton (k, l)-components, each consisting of a single vertex. Throughout Algorithm-
 2, we maintain M and C so that the following invariants hold for the current subgraph H at each iteration:
• For any u, v ∈ V , we have Mu,v = 1 if and only if there exists a (k, l)-component in H containing both u and v.
• The list C contains exactly the (k, l)-components in H.

The running-time analysis is more subtle. The following theorem establishes our main result.
Theorem 2. Algorithm 2, combined with the subroutines above, runs in O(n2 + m) time.
Proof. We analyze the time complexity of Algorithm 2 assuming the FindComponent, InCommonComponent, and UpdateComponents subroutines are implemented as described in Algorithms 3, 4, and 5, respectively. By Proposition 2, it suffices to bound the total running time of the InCommonComponent and UpdateComponents subroutines. The InCommonComponent routine is called once per processed edge, runs in constant time, and hence contributes a total of O(m) to the running time.
It remains to analyze UpdateComponents. Note that when the condition in line 5 evaluates to true, the algorithm constructs characteristic vectors and extends the list U in O(n) time. By Lemma 5, this branch is entered only O(n) times over the entire execution, contributing O(n2) time in total. Observe that, by Corollary 3, the time spent in line 11 during a single call is O(n). 4 Optimized implementations for special cases
For completeness, we describe optimized implementations for two important special cases of our problem. Both approaches have been discussed in the literature [8, 10, 11], but we present them here in a precise, self-contained form that integrates naturally into the framework of Algorithm 2. In each case, Algorithm 2 is extended with specialized implementations of the InCommonComponent and UpdateComponents subroutines. These variants achieve the same O(n2 + m) running time as in the general case, bu-
t they require less space and are considerably easier to implement and analyze.
9

4.1 The range 0 ≤ l ≤ k
When l ≤ k, the structure of (k, l)-sparse graphs simplifies significantly: their (k, l)-components cannot overlap. The following lemma formalizes this observation and can be proved by a reasoning similar to that of Corollary 1.
Lemma 6. If l ≤ k, then the (k, l)-components in any (k, l)-sparse graph H = (V, F ) are pairwise disjoint.
By this lemma, each vertex is contained in at most one (k, l)-component. Therefore, it suffices to store an array R ∈ (V ∪ {∅})V , where R(v) is a representative of the (k, l)-component containing v, or ∅ if v does not belong to any (k, l)-component. We initialize R(v) = ∅ for each v ∈ V when l < k, and R(v) = v when l ≥ k. Throughout Algorithm 2, we maintain R so that the following invariants hold for the current graph H at each iteration:
• For each v ∈ V , we have R(v) ̸= ∅ if and only if there exists a (k, l)-component in H containing v.
• For each u, v ∈ V with R(u) ̸= ∅ and R(v) ̸= ∅, we have R(u) = R(v) if and only if there exists a (k, l)-component in H containing both u and v.
Under these invariants, the implementation of the InCommonComponent and UpdateComponents subroutines simplify as follows.
Algorithm 6 In Common Component for 0 ≤ l ≤ k
Input: Two vertices u, v ∈ V . Output: true if there exists a (k, l)-component containing both u and v; false otherwise.
1: procedure InCommonComponentk,l(u, v)
2: return R(u) ̸= ∅ and R(v) ̸= ∅ and R(u) = R(v) 3: end procedure
Algorithm 7 Update Components for 0 ≤ l ≤ k
Input: A newly formed (k, l)-component C. Effect: Updates R so that all vertices of C share the same representative.
1: procedure UpdateComponentsk,l(C)
2: u ← head(C) ▷ Choose the first vertex of C as representative 3: for v ∈ C do ▷ Set u as the representative of each vertex in C 4: R(v) ← u 5: end for 6: end procedure
Proposition 3. Algorithm 2, extended with the subroutines above, runs in O(n2 + m) time.
Proof. The InCommonComponent subroutine takes constant time, while UpdateComponents requires O(n) time per call. By Lemma 5, the number of (k, l)-components formed during the execution of the algorithm is O(n), so the total time spent in UpdateComponents is O(n2). Combining this with Proposition 2, we get an O(n2 + m) running-time bound for the entire algorithm.
Hence, this specialized algorithm preserves the O(n2 + m) running time of the general approach while reducing its space usage from O(n2) to O(n), as the n × n matrix M is no longer needed. Note that this space bound excludes the space required to store the input graph.
4.2 The unweighted case
For the weighted problem, Algorithm 2 must process the edges of the input graph in decreasing order of weight. In the unweighted case, however, the edges can be processed in any order. We exploit this flexibility by choosing, for each edge, an arbitrary endpoint, grouping the edges by this chosen endpoint, and then processing them vertex by vertex. This enables a simpler and more space-efficient implementation. Since we process the edges vertex by vertex, there is no need to maintain the full n × -
n bit matrix to determine whether an edge uv can be inserted. Instead, we maintain an array I ∈ {0, 1}V and the list C of the (k, l)components, as in the general algorithm. While processing the edges incident to a given vertex u, the value of I(v) indicates whether there exists a (k, l)-component containing both u and v. If l < k, then we initialize C as an empty list; otherwise, we populate C with the singleton (k, l)-components. When processing the edges incident to a vertex u, we maintain I and-
 C so that the following invariants hold for the current subgraph H at each iteration:
10

• For each v ∈ V , we have I(v) = 1 if and only if there is a (k, l)-component in H containing both u and v.
• The list C contains exactly the (k, l)-components in H.
The array I is recomputed using a Recalculate subroutine whenever we move to a new vertex u. A global variable u0 ∈ V ∪{∅}, initialized to ∅, records the first endpoint of the last processed edge to detect when this recomputation is needed. With this setup in place, the implementations of the Recalculate, InCommonComponent, and UpdateComponents procedures are given below.

Input: A vertex u ∈ V . Effect: Recomputes I so that I(v) = 1 if and only if there is a (k, l)-component containing both u and v.
1: procedure Recalculatek,l(u) 2: I ← 0
3: for X ∈ C do
4: if u ∈ X then ▷ Component contains u? 5: for v ∈ X do ▷ Mark all vertices of X 6: I(v) ← 1 7: end for 8: end if 9: end for 10: end procedure
Algorithm 9 In Common Component for the Unweighted Case
Input: Two vertices u, v ∈ V . Effect: Update u0 and recompute I if u changes. Output: true if there exists a (k, l)-component containing both u and v; false otherwise.
1: procedure InCommonComponentk,l(u, v)
2: if u0 ̸= u then ▷ New first endpoint? 3: u0 ← u
4: Recalculatek,l(u) ▷ Recalculate I with the new endpoint u 5: end if 6: return I(v) = 1 7: end procedure
Algorithm 10 Update Components for the Unweighted Case
Input: A newly formed (k, l)-component C. Effect: Updates I and C to restore the invariants above.
1: procedure UpdateComponentsk,l(C)
2: C′ ← {C} ▷ Initialize the new set of components 3: for X ∈ C do
4: if X ̸⊆ C then ▷ Component not contained in C? 5: C′ ← C′ ∪ {X} ▷ Append X to C′ 6: end if 7: end for
8: C ← C′ ▷ Update C to contain the components of the new graph 9: for v ∈ C do ▷ Mark vertices of the new component 10: I(v) ← 1 11: end for 12: end procedure
