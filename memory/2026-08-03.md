### Catalog regeneration — clean once history was full

First pass of `npm run skills:generate` in `personal-site/` produced a
29-line `updatedAt` regression in `personal-site/lib/skills.generated.json`
— every affected `repo-skills/*/SKILL.md` timestamp collapsed forward to
`2026-07-17T12:15:20Z` (the timestamp of PR #458, the earliest commit
visible in the shallow clone). Root cause: this session started as a
shallow `git clone --depth=1`, and the generator's `gitCommitTime()`
helper (`personal-site/scripts/generate-skills-data.mjs:26`) then
returned the shallow HEAD's committer time rather than each file's
real earliest commit. This is the same class of environment-dependent
flakiness described in yesterday's log; the fix documented there
(pin to real history) would eliminate the trap.

`git fetch --unshallow origin` restored full history; re-running the
generator produced zero diff against the committed file. Trusted
submodules were already full-depth clones so no further unshallow
was needed.
