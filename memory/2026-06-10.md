### Shallow-clone trap (NEW gotcha — fold into a skill if it recurs)
- Submodules cloned with `git submodule update --init --depth 1 <path>` give every file inside the submodule the HEAD commit's timestamp when you run `git log -1 --format=%cI -- <file>`. The generator at [personal-site/scripts/generate-skills-data.mjs:26](personal-site/scripts/generate-skills-data.mjs:26) trusts that timestamp.
- Result: a local `make sync` writes `updatedAt: <today's HEAD time>` for every skill, then CI (`make sync-check`) regenerates with the real per-file commit times and fails on the diff.
- Fix this round: `cd <submodule> && git fetch --unshallow`, then re-run `make sync`. Did it for `gstack`, `marketingskills`, `open-design` here; `mattpocock-skills` was already deep.
- Yesterday's PR #348 likely shipped the same wrong timestamps (didn't get caught because... unclear; possibly CI also had a shallow checkout, possibly the diff just wasn't dramatic enough to fail). Today's PR #352 corrects the catalog back to real per-file times.
- **Recurring pattern for worktree runs:** prefer `git fetch --unshallow` on the touched submodule before `make sync`. Or: skip `--depth 1` on submodules you actually intend to `make sync` against. [TOOLS.md](TOOLS.md) already warns about disk cost of full submodules — there's a real tradeoff here, but for the four sources the generator reads (`gstack`, `marketingskills`, `mattpocock-skills`, `open-design`), full clones are mandatory.
