### Cold-worktree gotcha — this session's DoWhiz + first-tree submodule
### pointer was OLDER than what main records

When the worktree opened, `git submodule status` showed `+` on DoWhiz and
first-tree — but this time the `+` meant their local checkouts were
BEHIND the parent-repo pointer, not ahead. `git ls-tree HEAD <path>` was
authoritative (DoWhiz expected `8c5b2e49`, worktree had `6b6c1653`).
Fixed with `git submodule update current-projects/DoWhiz current-projects/first-tree`
before doing anything else. Then bumped from that clean baseline.

Take-away for next cold worktree: run `git submodule status` first and
inspect `+` prefixes; a `+` can mean either direction. Compare against
`git ls-tree HEAD` before assuming it's an upstream advance.
