### Timestamp-drift CI failure (learned)

First push failed `sync-check`: `personal-site/lib/skills.generated.json` had `updatedAt: "2026-07-24T13:14:48.000Z"` for `frontend-design`, but CI regenerated it as `"2026-09-22T12:47:19.000Z"` (my own branch commit time). Root cause: I ran the generator locally **before** committing the SKILL.md edit, so `git log -1 --format=%cI SKILL.md` returned the previous upstream commit time — the working-tree edit wasn't in git history yet. CI checks out with the edit already committed, so its `git log` returns the new commit time. Fix: rerun `npm run skills:generate` **after** the commit, then follow-up commit.

**Rule for future sweeps:** the correct order is (a) edit + commit, (b) regenerate, (c) commit the regenerated JSON. Or: `git add -A && git commit`, then re-run `make sync` and commit any resulting diff. `personal-site/scripts/generate-skills-data.mjs` derives `updatedAt` from `git log`, and only committed history is visible to it.
