### Gotcha for future J.A.R.V.I.S. instances: don't trust the first `make sync`

The FIRST `make sync` I ran this session produced **wrong** `updatedAt`
timestamps for 30 skills (advanced them to `2026-07-05T10:21:08.000Z`, the
committer time of `d8c1bb6` "chore: bump open-design submodule to latest
(2026-07-05)"). The regeneration was self-consistent so it looked correct
locally, and I opened PR #478 with the diff — CI (`skills-sync-check`)
correctly rejected it with the reverse diff (regenerating the OLDER, correct
dates like `2026-04-30T22:50:16.000Z`).

Root cause I can point at: `d8c1bb6` did **not** modify any of those SKILL.md
files (`git ls-tree d8c1bb6 <path>` and `git ls-tree d8c1bb6^ <path>` yield
the same blob hash), but running the generator's exact `git log -1
--format=%cI -- SKILL.md` (cwd = the file's dir) inside my session at that
moment nevertheless returned `d8c1bb6`'s date instead of the real last-touch
`da2b7df` (2026-04-30). Later in the same session, from the same working
directory, from the same HEAD (`6fa5660`), the same command correctly
returned `da2b7df`. So it wasn't a code bug in `generate-skills-data.mjs`;
git itself gave inconsistent answers across two invocations. Best guess:
some intermediate `git submodule update --init` / `git reset --hard` inside
`trusted-external-repos/open-design` (which had been checked out into a
broken all-files-staged-for-deletion state on this cold worktree) briefly
poisoned pack/index state that git's `log --path-filter` consulted; the
second invocation was after the state had settled.

**Rule of thumb for the next scheduled run:** before opening a PR with any
`personal-site/lib/skills.generated.json` diff, run `make sync-check`. It
mirrors CI's discipline (`git diff --exit-code` after `make sync`) and will
scream if your regeneration disagrees with itself. On this branch's fresh
worktree today the workflow that mattered was:

1. `git submodule update --init trusted-external-repos/{open-design,marketingskills,mattpocock-skills,gstack}`
2. If any of those show up as "staged for deletion" via `git status` (open-design did today), `git -C <path> reset --hard HEAD` to unbreak the checkout.
3. `make sync`
4. `make sync-check` — MUST pass. If it doesn't, do NOT commit the diff; re-run `make sync` and re-check. If it stays stable across two runs and still diverges from HEAD, that's real drift worth committing.
