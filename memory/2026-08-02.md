### Follow-up worth logging

The generator's `gitCommitTime()` (`personal-site/scripts/generate-skills-data.mjs:26`)
is intended to produce deterministic per-file timestamps, but this
sweep's CI/local divergence is the second time (after PR #504 → #502)
we've had to refresh timestamps that then got reverted by a later
regen. Root cause worth a proper investigation in a future session.
Options to consider:

- Pin the `git log` call to an explicit `HEAD` ref rather than the
  current checkout (`git log -1 --format=%cI HEAD -- <file>`).
- Skip the git lookup entirely on files under `repo-skills/` and use
  a fixed value; only compute git times for the submodule sources
  whose commit time actually maps to upstream history.
- Or: stop tracking `updatedAt` in the generated JSON, source it at
  build time only.
