## Crumble circuit, Craig Gidney, qccd.academy

Bingran asked to "check" three links: a Crumble circuit, a Google search for Craig Gidney, and https://www.qccd.academy/. Done with a workflow (four investigators, each followed by an independent verifier).

The circuit:

- It is byte-identical to Crumble's built-in example "Bacon-Shor Code / Interleaved (XZXZ) / Memory (H) / 5x5x3" (in `glue/crumble/crumble.html` of quantumlib/Stim). It is a 3-round Z memory on the 5x5 Bacon-Shor code [[25,1,5]], built only from R, MZZ, MXX and a final M.
- In Stim it is correct: 32 detectors and 1 observable, all deterministic; the schedule has no conflicts; the MARKZ/MARKX pairs bracket the detecting regions of DT(4,1,1) and DT(2,4,3).
- The detector set is incomplete: the deterministic parity space has dimension 41, the declared set spans 33. The 8 missing parities are column-block products of the odd ZZ gauges in round 1 and at the final readout. Paste them in the "refined" basis (replace the 4 affected detectors with column blocks); plainly appending them breaks `decompose_errors`. Adding them lowers the pymatching LER by about 10-14% under native pair-measurement noise and does not change the distance.
- Circuit distance is ceil(d/2) = 3 under EM3-style pair-measurement noise (DEPOLARIZE2 on the measured pair): an XX error on a vertical ZZ-measured pair commutes with the measurement and covers two rows of the X logical. Distance is 5 under single-qubit pair noise and under ancilla+CNOT decompositions (SD6, SI1000).
- The empty TICKs cost 35-72% more LER if a noise model idles every tick.
- Scripts and data were in `/tmp/crumble_check/` (temporary).

## QCCD site restyle: how to contribute cleanly (plan only, nothing implemented)

- Upstream has no contribution process. All 7 PRs are the owner's own, merged as merge commits within seconds, with no review. CI has no pull_request trigger and fails on every push (`qccd.gadget` missing). Deploys are manual. The owner commits each feature as a pair: toolchain on `compiler`, site on `website/invitations`.
- A PR has to be cut from `upstream/website/invitations` and opened with `--base website/invitations`. `gh pr create` defaults to `main`, which would drag in 34 of John's unmerged commits (+714k lines). Branching from `local-preview` would add 101 compiler commits. The combined tree is only for builds, in throwaway worktrees.
- Hard constraints:
  - Inside `<main>` the change must be CSS-only: pinned reader comments are anchored by a DOM path.
  - Keep the 16 `STYLE` variable names, `PAGE`/`STYLE`/`HASH_JS`/`FOOTER`/`with_nav`, and the IDs: compiler-side code imports them.
  - Chrome tokens need their own prefix (`--sn-*`). Studio pages reuse `--accent` and other names with different values.
  - Leave `render.py`/`theme.py`, the 189 MB of seed HTML and `/gadgets/showcase|demo` alone.
- Split into PR 1 (tokens, no visual change) and PR 2 (restyle, one page family per commit). Email John (yezhuoyang@cs.ucla.edu, cc Ke Sun) with mock screenshots before any code.
- Testing baseline: `tests/site.mjs` already fails on 83 of 401 pages on the unmodified build, the same set before and after a CSS edit, so report a delta. On macOS, `tests/test_site_comments.py` skips silently unless `CHROME` is set.
- Dev tools (fast build in about 6 s, watcher, before/after screenshot diff) are in `/tmp/qccd_devloop_tools/`. Copy them out of /tmp before relying on them. The full plan was in `/tmp/qccd_plan.txt`. The dev-loop scratch worktrees and branch were removed.
